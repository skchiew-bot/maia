## Residual risks of closed gaps

These are not open engineering items: each is accepted, awaits a decision, or is an operating limit. They are listed
so nobody has to rediscover them.

| Residual risk | Source | Decided by or handled in |
| --- | --- | --- |
| Egress is not restricted: a session can send out whatever it holds (the `session` part of its profile, the Claude token, its ingest token) | O-14, O-9, T-3 | CEO decision, P-20 |
| The session's ingest token is readable by the model: it can forge hook and MCP events for its own session (T-3), and the push gateway accepts the same token during a turn, so a manipulated model can push what `push.refs` allows. Liveness and metering no longer depend on it (sidecar token, G-44) | T-3, R-01, wave 2 residual | Accepted; narrowed by `push.refs`, turn-scoped gateway access and the rate limit |
| Credentials that are not git (a deploy API token, a cloud CLI) have no proxy: do not put one in a profile's `env` for a session type | wave 2 residual | Ops rule, [credential isolation §4 item 11](../runbooks/credential-isolation.md#4-the-supervisor-host) |
| `supervisor.isolation: "none"` (the development default) leaves the profiles file, the keys and the service clones readable by sessions | G-01 | Development only; production refuses it |
| A non-root aocd with a `sudo` runner is not supported: the sidecar cannot read the 0600 transcript and aocd cannot kill another user's process | G-01 | Design limit |
| A session's own `HOME` keeps what the agent writes there across that session's turns; `~/.claude/settings.json` gets the workspace-settings rules before every turn, other Claude Code state there is not checked | G-01 | Accepted |
| A process that calls `setsid()` escapes the end-of-turn kill of the turn's process group. It runs as the session user, holds no push credential, and its ingest token dies with the session | wave 1 F-12 | Accepted |
| Nothing fetches the protected remote: the service clone learns a branch from AOC's own pushes (and, for a first promotion, from the project repository's view). The push lease turns a wrong guess into `default_branch_moved`, never into an unchecked push | G-04 | Accepted |
| Pin tags (`aoc/*`) stay in the service clone and are not pushed, so GitHub ruleset C is unused | G-04, §8 | Platform architect decides whether pins should also reach the remote |
| A promotion candidate that fails git's object checks is refused; accepting known old damage means setting `fetch.fsck.<msg-id>=warn` in that project's clone | G-04 | Operator action when it occurs |
| A local-path remote runs its hooks inside the push, with the credential (tests and same-host mirrors only; it must belong to root) | G-04 | Use ssh or https remotes |
| The push gateway's repository is a staging copy: objects of a refused branch stay until `git gc --prune=now` is run by hand, it creates SHA-1 clones, deletions and forced pushes are unsupported, its per-session rate limit is in memory and resets when aocd restarts, and one slow upstream push holds a project's push lock for up to its 2-minute deadline | wave 2 residual | Operating notes in [credential isolation §4 item 11](../runbooks/credential-isolation.md#4-the-supervisor-host) |
