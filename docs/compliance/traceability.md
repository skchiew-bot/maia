## Method and status rules

* Every MUST / binding statement in §1–§15, the §12 guardrails and R1–R17 is an atomic row.
* **Implemented** — merged code does it **and** a merged, passing test demonstrates it. Where two modules must
  cooperate, both sides exist and agree on the contract in `packages/contracts/src/services.ts`.
* **Partial** — part of it is merged and tested, but a part is missing, untested, wrong by default, or undermined
  by an open finding of the threat model (`docs/security/threat-model.md` §6, items O-n).
* **Missing** — no merged code does it.
* **Process-only** — an organisational obligation (CEO, compliance lead, ops); software can at most support it.
* **N/A** — not applicable to software.
* Paths are repo-relative; `file:line` points at the decisive code. Tests are `file › "test name"`.
* Gap ids (`G-xx` software, `P-xx` process) refer to [gaps.md](gaps.md).

What stays open is concentrated in four places:

1. **§3 credential isolation (P0).** Sessions get only allowlisted env plus their own profile, but they still run as
   the aocd OS user with aocd's `HOME` (threat model O-1), and promotion / rollback git runs in the project's
   agent-writable repository with the promotion credential (O-2). Until both are fixed, file permissions protect the
   credential profiles, the KEK and the database from nothing (G-01, G-04).
2. **Integrity of agent-reported data (P1):** provenance trailers are self-asserted (G-25), the sidecar shares the
   agent's token so usage can be forged (G-44), spooled usage is dropped on replay (G-10), evidence packs check
   anchors in-chain only (G-42).
3. **FX defaults (P1):** with the shipped config no weekday is ever stamped live and the reconciliation compares the
   wrong BNM session (G-36).
4. **UI pages (P1):** every operator and portal page is a placeholder (G-09).
