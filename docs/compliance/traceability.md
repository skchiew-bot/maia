## Method and status rules

* Every MUST / binding statement in §1–§15, the §12 guardrails and R1–R17 is decomposed into atomic rows.
* **Implemented** — merged code does it **and** a merged, passing test demonstrates it. Where two modules must
  cooperate, both sides exist and agree on the contract in `packages/contracts/src/services.ts`.
* **Partial** — some of it is merged and tested, but a part is missing, depends on an unmerged module (most
  often the supervisor), is untested, or its test is red at the baseline.
* **Missing** — no merged code does it (contract types or event definitions alone do not count).
* **Process-only** — an organisational obligation (CEO, compliance lead, ops); software can at most support it.
* **N/A** — not applicable to software.
* Paths are repo-relative; `file:line` points at the decisive code. Tests are `file › "test name"`.
* Gap ids (`G-xx` software, `P-xx` process) refer to [gaps.md](gaps.md).
